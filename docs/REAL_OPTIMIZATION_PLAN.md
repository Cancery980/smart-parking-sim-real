# 真实照片检测继续优化

开始日期：2026-11-01。基线为已发布 v1.1、提交 `d40f28aa1b804416e0d112f42ed68112ef157da9`。用户希望继续提高车辆检测精确率和召回率；99.99% 是希望接近的方向，不是预先宣称能够达到的成绩。

## 不变的边界

- 保留已发布版本、全部原始照片、原标注与旧实验记录；原 36 张测试图已被查看，后续报告同时明确这一点。
- 只用开发集选择模型、推理配置及置信度阈值，不根据旧测试图单独修补规则或筛除困难照片。
- 在训练、开发和旧测试之外，按元数据冻结新增验证照片；先选定最终方案再打开新增验证结果。优先完整日期隔离，若数据不足则记录实际可行范围。
- 真实照片依然只负责视觉验证；不改变仿真三态阈值、米制地图、单会话或梁可接口。运行时不读取占用真值。

## 实施与选择

1. 先检查作者开源代码、官方训练/推理实现与现有开发误差。复用 Ultralytics、现有评分与几何工具。
2. 在独立工作区比较更大的预训练检测器及增加训练照片；训练数据不跨入开发/测试日期。实验权重先保存在工作缓存，不自动覆盖生产模型。
3. 开发集选型先要求 Precision、Recall 都不低于 v1.1 的 conf=0.20 开发基线（TP943/FP51/FN9），再最大化 `min(precision, recall)`，并报告 F1、两项指标、占用误差和 CPU 耗时。阈值网格预定为0.20至0.80、步长0.05。若无合格升级则保留基线；不把提高阈值造成的单项改善称为两项提升。此规则在新模型完成和任何新增外部评测前固定。
4. 冻结最终配置后，在原测试集与新增未见验证集上对照 v1.1；不因验证结果调整阈值或删除失败。提升不成立时保留基线并如实记录。
5. 有效改进接入真实照片页，更新报告、复现脚本、免安装包与 GitHub 发布；若 CPU 成本提高，要实际测量并说明。

## 冻结后的实测结论

最终按既定开发规则选中747图训练的YOLOv8s、ROI裁剪、车辆检测门槛0.35，占用证据保留门槛仍为0.20。两个训练阶段分别完成60轮、20轮；一次额外TTA未胜出，保留其开发记录。随后仅执行一次两组最终CPU评测，未根据测试结果调整模型、门槛或数据。

PKLot历史36图精确率由96.56%变为98.48%，召回率由98.80%变为98.89%；CNR外部54图精确率由76.72%变为88.06%，召回率由71.78%降至61.67%，F1也下降。假空闲分别从0增至1、从154增至243。原场景检测改善并未迁移成整体占用改善或跨场地改善，不能声称达到99.99%。保留v1.1权重、发布和全套对照，当前源码将开发选定候选作为可复现实验配置展示；它不是跨场地普遍最优的结论。逐图预测、完整分母和失败案例见最终报告。
