# 梁可从这里开始

你可以先运行演示，理解数据怎样流动，再接自己的规划代码。前两步不需要学 Git；修改代码时才需要安装 Python。胡轩铭已经提供图像、检测、三态占用、界面和停车会话，你主要接入选位与路径规划。

[返回项目首页](../README.md) · [公开仓库](https://github.com/Cancery980/smart-parking-sim-real) · [接口字段](CONTRACT_V1.md)

## 第一步 看界面和完整流程

先看[二维仿真运行截图](../reports/ui_live.png)。课程主体是胡轩铭的场景、真实 YOLO 推理、三态占用、界面与会话，连上随包参考规划后可以完整演示申请、实际停车确认和寻车。推荐位置与实际位置分开保存，寻车必须到实际车位外的接近点。[课程范围与验收](课程范围与验收.md)说明双方归属；已有参考功能全部保留，你可以在理解接口后替换。

当前的选位与 A* 来自随包的 [参考规划实现](../parking_hu/reference_planner.py)。它让项目先能完整运行，也给你可核对的输入输出；它不是已经替你提交了个人实现。

## 第二步 下载演示包

下载 [ParkingDemo-Windows.zip](https://github.com/Cancery980/smart-parking-sim-real/releases/latest/download/ParkingDemo-Windows.zip)。也可以从 [Releases 页面](https://github.com/Cancery980/smart-parking-sim-real/releases) 查看版本与附件。

**已有 v1.2 运行证据：** [实拍界面13项](../reports/real_photo_portable_validation.json)、[停车流程6项](../reports/windows_optimized_flow_validation.json)。它们检查实际运行与交互，模型精度另看评测结果。v1.2.1 新增胡模块的车辆登记表单并调整默认入口，既有模型实验不计作新版重复测试；本次实际EXE的[6项停车流程](../reports/course_alignment/portable_flow_validation.json)、[5项界面检查](../reports/course_alignment/browser_validation.json)和[8项登记实操](../reports/course_alignment/registration_final_validation.json)均通过，具体交付状态见[交付核验](../reports/交付核验.json)。latest链接下载到的版本以Releases说明为准；需要比较时，可打开[v1.1.0基线发布](https://github.com/Cancery980/smart-parking-sim-real/releases/tag/v1.1.0)，旧包仍使用PKLot清单。

完整解压，保留所有文件和子目录，再双击 **ParkingDemo.exe**。加载结束后会自动打开本机浏览器，默认二维仿真页地址为 `http://127.0.0.1:8766/`。运行时保留启动窗口，结束时关闭窗口即可。演示包自带运行环境和 CPU 模型；GitHub 网页只提供下载，不会替你运行 Python。

先在空闲会话展开“＋ 登记新车辆”，填写名称或代号、动力类型与无障碍资格（待确认/无/有），点击“登记并选用”后自动选中。已有四个示例车辆仍可选；重置会话和场景保留新增档案，退出程序后清空。已有推荐或已停车时不能登记新车辆。

再按以下顺序试停车流程。充电需求在本次需求表单中选择；YOLO 只提供车辆框和占用证据，不推断这些登记资格：

1. 打开“检测框”图层，切换空场与普通场景，观察每次重新检测。
2. 选一辆模拟车辆，填写需求，分别尝试“少走路”和“近出口”。
3. 确认实际停车位置，可选择与推荐不同但没有车辆冲突的位置。
4. 点“从电梯出发”或在地图人行通道上点选起点，生成寻车路线。
5. 更新场景后重新寻车，确认目标仍为实际停车位；最后确认离场或重置。

完成主线后，可从首页进入“真实停车场照片”查看扩展对照。[v1.2 外部页面截图](../reports/real_photo_external_ui.png)可预览界面。照片只验证视觉，没有把像素接成真实米制路网。

当前源码照片清单有 **108 张：18 张 PKLot 开发、36 张 PKLot 历史测试、54 张 CNRPark-EXT 外部验证**。PKLot 来自两个场地、三个视角、三种天气，历史测试覆盖 32 个日期；CNR 来自另一场地，包含 9 台相机、20 个日期及三种天气。旧 36 张已经公开分析，用于历史回归；CNR 外部照片未参与训练或选型。

照片使用原始像素和预先标定的车位多边形，主要验证视觉。你接入的规划接口仍使用二维仿真的米制地图；不用把照片像素换成米，或给没有真实路网的照片画 A* 路线。

可再花两分钟试真实照片：在 v1.2 页面选择 CNRPark-EXT 和“外部验证”，筛选视角、天气后点击“运行真实 YOLO 检测”。可以关闭图层看原图，也可以点车位看置信度、中心是否在位及相交比例。“查看上游原始照片”能核对来源；“重新运行真实检测”会再次推理。切换照片后旧结果清空，原来的停车会话不受影响。

车辆数字按开发集选定门槛统计“已接受框”；侧栏显示实际门槛。“低置信证据”图层用虚线显示待确认框，它们不计入已接受车辆数。**全部置信度 ≥0.20 的框仍参与车位占用判断**，占用高阈值仍为 0.50、相交比例仍为 5%，关闭图层不会删掉证据。浅蓝细虚线是推理区域；车位未完整覆盖且没有明确车辆证据时显示不确定，已有高置信中心证据仍可判占用。详情覆盖比例是面积比例，不是识别准确率。

[实拍优化报告](../reports/real_optimization/RESULTS.md)、[最终实测JSON](../reports/real_optimization/final/summary.json)及[浏览器版报告](../reports/real_photo_report.html)已保留全部结果。选定门槛0.35时，PKLot历史精确率/召回率为98.48%/98.89%，CNR外部为88.06%/61.67%。相对v1.1默认，外部精确率提高，但召回率由71.78%下降至61.67%，假空闲由154增至243次；PK假空闲也从0增至1次。不能把它称为全面提升。

报告同时比较共同0.20门槛，保留[v1.1历史结果](../reports/real_photos/RESULTS.md)。外部结果只覆盖这一个新场地的有限条件，项目未承诺或证明99.99%正确率。


## 第三步 准备可修改的源码

免安装包用于演示。要改 Python 文件，回到 [仓库首页](https://github.com/Cancery980/smart-parking-sim-real)，点绿色 **Code → Download ZIP**，将源码解压。进入能同时看到 `README.md`、`setup.ps1` 和 `parking_hu` 的那一层文件夹。

安装 Python 3.12，并确保终端可执行 `python`。在源码文件夹的资源管理器地址栏输入 `powershell` 后回车，即可在正确目录打开命令窗口。执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

这一步下载依赖并建立本项目的 `.venv`，需要联网。若提示 Python 版本不对，可以使用实际安装路径，例如：

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1 -Python "C:\Python312\python.exe"
```

上面的路径只是示例，应替换为你电脑中 Python 3.12 的路径。安装成功后先验证未修改的项目：

```powershell
.\.venv\Scripts\python.exe scripts/check_plugin.py --planner examples.liang_adapter:Planner
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Planner examples.liang_adapter:Planner
```

契约检查成功会显示 `9 contract checks passed`。第二条命令打开源码版界面，默认使用 `http://127.0.0.1:8765`。如果浏览器没有自动打开，等待窗口显示本地地址后手动访问该地址。修改代码前先关闭这一轮启动窗口，避免旧进程继续占用端口。

## 第四步 在接线文件中换成自己的算法

优先打开 [examples/liang_adapter.py](../examples/liang_adapter.py)。这个文件已经有无参 `Planner` 类和两个方法：

```python
class Planner:
    def plan(self, context: dict, request: dict) -> dict:
        ...

    def find_vehicle(self, context: dict, request: dict) -> dict:
        ...
```

保留这两个入口，把文件里对 `self._implementation` 的委托逐步换成你自己的计算。当前样例能运行，是因为它调用了参考规划器；只改文件名而仍委托参考实现，不代表完成了自己的规划模块。

| 你收到的数据 | 应怎样使用 |
| --- | --- |
| `context["map"]` | 固定 52 位地图、车位类型、接近点和通行域 |
| `context["snapshot"]` | 当前有效帧的三态占用与全部保留车框障碍 |
| `context["vehicle"]` | 模拟车辆动力类型、无障碍资格和角色 |
| `context["session"]` | 当前会话；寻车时从这里读实际车位 ID |
| `request` | 本次需求、偏好、操作和手选人行起点 |

`plan` 处理申请和重规划：先检查需求与资格，再筛选可用车位，计算入场、出场和到电梯三条合法路线，最后按偏好排序。`find_vehicle` 使用实际停车记录和手选起点，返回到车位外 `ped_access_m` 的人行路线。

新增登记的车辆 ID 由胡模块生成。规划器应读取当前 `context["vehicle"]` 中的动力类型和资格，不要假设只有四个预置 ID；登记档案与会话仍由胡模块管理。

输出是普通字典，必需字段和失败码见 [CONTRACT_V1.md](CONTRACT_V1.md)，完整示例见 [planner_context.json](../examples/planner_context.json)。不要另造地图坐标、不读 `scene_truth` 修补推荐，也不要让规划器改会话或车辆实体；这些交给胡模块。路线必须保留经过的全部图节点，不能靠只返回两端点通过检查。几何、排序及投影规则见 [详细交接说明](PLANNER_HANDOFF.md)。

也可以另建源码根目录下的 `liang_planner.py`，只要提供同样的 `Planner` 类。启动参数中冒号前是可导入模块名，后面是类名，不带 `.py`：

```powershell
.\.venv\Scripts\python.exe scripts/check_plugin.py --planner liang_planner:Planner
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Planner liang_planner:Planner
```

## 第五步 检查自己的模块

每次修改后，在同一个源码根目录运行指向**自己模块**的 `check_plugin.py --planner ...`。它检查返回字段、主要需求与资格情况、车位类型、三条路线和寻车。它使用固定检测数据，9 项通过只说明这些契约用例通过，不等于真实图像下的全部功能和性能通过。

随后用自己的 `-Planner` 参数启动界面，检查正常申请、专用位失败、实际停车偏离、非法寻车起点和场景变化后的重规划。程序会校验插件返回；返回结构或路线不合法时，应修复算法或适配层，不绕过校验。

已有检查与对照实验可这样运行：

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
.\.venv\Scripts\python.exe scripts/run_e2e.py --planner examples.liang_adapter:Planner --out reports/e2e_external
.\.venv\Scripts\python.exe scripts/run_pairing.py --planner examples.liang_adapter:Planner --output reports/liang_pairing
```

第一条运行随包确定性测试。第二条用指定插件和真实 YOLO 推理执行 E01—E08，将场景和结果另存到 `reports/e2e_external`。第三条复用冻结的真实检测缓存运行二态与三态对照，并将结果另存到 `reports/liang_pairing`。第二、三条都应明确传入你正在开发的模块名，不能仅根据先前界面的启动设置判断它们使用了哪个模块。

这里的 E01—E08 和 I01 使用**合成图像上的真实模型输出**，验证停车业务与规划。实拍照片的车辆检测和车位占用另行评估，不能把两组实验的图像数、正确率或路线结果合并。

如果你另建了 `liang_planner.py`，真实端到端验收命令为：

```powershell
.\.venv\Scripts\python.exe scripts/run_e2e.py --planner liang_planner:Planner --out reports/e2e_liang
```

同样将配对实验的 `--planner` 改为 `liang_planner:Planner`。`run_e2e.py` 未指定 `--planner` 时仍使用默认参考规划器；使用单独的输出目录可以保留原有默认 E01—E08 证据。检查新目录中的 `results.json` 及各场景实际结果，失败时修复受影响功能再复验。

## 第六步 交回代码

把改动的规划文件、使用的模块参数、测试结果及已知问题一起交给胡轩铭，即可按同一接口整合。不要只交截图，也不要把本机 `.venv` 或运行时缓存当作源码。

如果准备使用 GitHub 协作，可以 Fork 这个公开仓库，在自己的副本中保存改动，再向原仓库提交 Pull Request。公开仓库允许浏览和下载，主分支写入权限由仓库管理者控制；不需要为运行演示提供自己的账号。
